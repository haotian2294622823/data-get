# 工序0材料工程宽表修改计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**目标**：最终宽表每个制造 `lot_no` 一行，材料工程展开为工序0。每个卷线列组对应一个独立的卷线材料 LOT，展示对应的工艺、设备和不良。E-Core 与 I-Core 展示材料 LOT 和每次执行的工艺信息。

**实现范围**：Python 标准库。修改材料宽表生成和最终 CSV 的列排序。页面导出和 `merge_csv.py` 通过现有 `merge_tables()` 入口使用新规则，数据库取数和原始 CSV 存档沿用现有流程。

## 输出约定

列顺序为「制造批次基本信息 → 工序0 → 制造工序1及后续」。工序0内部沿用 E-Core、I-Core、卷线的顺序，每种工程从 1 独立编号。卷线按不同材料 LOT 编号，依照材料在该制造 LOT 中的首次使用顺序。E-Core、I-Core 按每次执行编号，同一材料内部按 `pass_order` 数值和 `process_key` 排序。

| 工程 | 每个编号对应的内容 | 示例 |
|---|---|---|
| E-Core | 材料 LOT、原始工程名、执行键、道次、工艺字段 | `工序0_E-Core1_material_lot_no` |
| I-Core | 材料 LOT、原始工程名、执行键、道次、工艺字段 | `工序0_I-Core1_process_key` |
| 卷线 | 一个材料 LOT 的卷线工艺、设备与不良 | `工序0_卷线1_机台设备1_machine_name`、`工序0_卷线1_不良1_defect_qty` |

例如制造批次 `E100` 依次使用卷线材料 `M200` 和 `M201`。`E100` 的同一行会有 `工序0_卷线1_material_lot_no=M200` 和 `工序0_卷线2_material_lot_no=M201`，两组的执行键、参数、设备与不良各自对应。制造记录多次引用 `M200` 时，仍共用卷线1的列组。

正常数据中，每个卷线材料 LOT 对应一次卷线执行。若读到同一卷线材料 LOT 下有多个有效执行键，第一条使用该材料的常规列，额外记录保留在同组的 `执行2_…` 等子列，并提示核对原始数据。`卷线2` 始终留给另一个材料 LOT。

每个制造 LOT 预计使用合计 10 个不同的 E-Core、I-Core 材料 LOT。以这两类关联到的材料 LOT 并集统计，同一材料的重复用料记录或多次工程执行只计一个材料 LOT，卷线单独计数。10 个作为样本核对的预期值，实际材料和工程执行按原始记录保留。

## 动态拼接规则

- 每行从制造用料记录收集实际使用的 `material_lot_no`，匹配前工程的 `lot_no`。按匹配到的工程与材料生成列组，编号由记录顺序产生。卷线材料有几个就生成几个卷线列组。E-Core、I-Core 的列组数随实际执行次数变化。
- 工艺字段来自前工程 CSV 的表头，按计划保留有值的可选字段。卷线设备、不良的编号也由实际明细生成。分片及最终表按生成的列名对齐不同制造 LOT。
- 将工程名称及别名、工程排序、编号依据和展示的明细类型集中到 `lot_extract/material_rules.json`。默认规则设定 E-Core、I-Core 展示工艺，卷线同时展示设备和不良。合并函数读取同一份规则并处理各类工程。未识别工程按计划进入异常分组，便于发现公司数据库中的新名称。

## 输出精简规则

1. **卷线不良按记录编号。** 使用 `不良1_defect_code`、`不良1_defect_name`、`不良1_defect_qty` 等列。同一执行有多条不良就依次编号，名称填在单元格里。这样不同批次出现新的不良名称时，可以复用同一列组。每条记录保留原数量。
2. **精简重复属性和全空列。** 工序0每组直接展示材料 LOT 和该次执行的工艺字段。材料批次表的其他属性保留在原始存档，工序0不随每次执行重复展开。对工序0的可选字段，只有整次结果都为空才省略，`0` 等有效值保留。材料 LOT 和执行关联字段保留为固定列。

800–1,000 列用作公司数据的验收参考。实际宽度由工程执行数、卷线明细数和有值字段数决定，每次有效执行完整保留。
